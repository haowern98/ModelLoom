# GGUF model library

The shared Import GGUF button accepts local `.gguf` files from every library tab. Importing registers the existing file; it does not copy, download, convert or load it. All shows every entry. Models shows full models, including standalone drafters and targets with embedded MTP. Speculative heads shows recognized extracted MTP, EAGLE-3, DFlash and DSpark companion files.

Classification uses GGUF contents, not filenames. EAGLE-3 uses the `eagle3` architecture. DFlash and DSpark both use `dflash`; DSpark requires a complete compatible Markov tensor pair. Shared fusion/norm shapes, target-layer metadata, reduced-vocabulary mappings and DFlash2 selector/convolution groups receive structural checks. Tensor-directory parsing is bounded by the existing metadata buffer and operation limits. Unsupported extensions, GGUF adapters and malformed metadata are rejected.

MTP classification reads architecture-scoped block and NextN counts, then checks the common NextN projection and normalization signatures at every declared prediction block. Dynamic block indices support dense/MoE families and multiple prediction heads. A complete ordinary trunk remains a model, including converters that advertise NextN without exporting its tensors. Complete NextN blocks with no ordinary trunk are classified as an MTP companion. Partial trunks, incomplete prediction signatures, inconsistent shapes and undeclared/out-of-range NextN blocks are rejected. This is structural classification across recognized common signatures; it does not grant MTP execution support to every architecture.

Import inspection establishes bounded metadata and file identity. It does not validate every tensor, prove compatibility with a target/runtime, or enable speculative inference. Companion selection and execution remain separate work. Imported heads display a method badge and cannot be selected as ordinary targets or opened in target configuration.

Private source records contain optional bounded `speculativeHead` and `classificationVersion` metadata. Existing records remain valid and the SQLite table schema is unchanged. Head registration uses a caller-bound main-only owner command; the renderer cannot submit paths, classifications or owner commands. Importing a head preserves the selected target and history owner. Restart restores all entries and selects only a full target, including when the newest entry is a head. A heads-only library has no selected target.

On startup, legacy records receive one sealed header-only reinspection before selecting the target. The saved size/mtime must still match. This does not hash or read model payloads. A caller-bound main-only `reinspectImport` operation can update metadata only for an existing immutable file identity while inference is inactive, preserving import timestamp and registration order. Failed or unavailable reinspection marks the entry unavailable and does not persist guessed metadata. Fresh payload identity verification still precedes model activation. Once reconciled, `classificationVersion=1` avoids repeated startup inspection.

Removal forgets only the library record and leaves the original file intact. Duplicate content retains one entry and its original import timestamp. Missing or changed files are reconciled through the existing file-availability checks. Existing import busy-state and file-ownership rules remain in force.

Regression coverage: core `gguf-heads.test.ts`, `gguf-mtp.test.ts`, `companion-import.test.ts` and `reinspect-import.test.ts`; desktop `speculative-import.test.ts`, `speculative-repair.test.ts` and renderer `ModelsPage.test.tsx`, alongside existing library, import, runtime, configuration and removal suites.
